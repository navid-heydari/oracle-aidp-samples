# Snowflake → AIDP Migrator — MVP-1 design

**Date:** 2026-09-09 · **Status:** design, approved in outline, pending spec review
**Plugin:** `oracle-ai-data-platform-workbench-snowflake-migrator`

## 1. Goal

**Build the plugin.** The deliverable is a reusable Claude Code plugin that can
investigate, plan, and structurally clone *any* Snowflake estate onto AIDP. It is not a
one-off migration of a particular customer, and it is not a data-transfer utility.

A named engagement supplies the shape of the requirement and the first validation case;
see `../../RAPPI-CONTEXT.md` (customer-confidential — do not restate its figures here).

### 1.1 MVP-1 scope

| # | Requirement |
|---|---|
| 1 | Plugin skeleton, following the existing AIDP plugin conventions |
| 2 | Investigate a Snowflake environment: list tables and views with row counts and sizes |
| 3 | Produce a high-level migration plan and present it to the user |
| 4 | Create a medallion architecture and start the soft clone (schema only) |

Item 5 of the original MVP — compute calculation and cost proposal — is **deferred**.

### 1.2 Non-goals for MVP-1

Data movement · view translation · stored procedures · UDFs · tasks · streams · pipes ·
dynamic tables · Fivetran or any ingestion path · ADW/ALH/ExaCS serving tier ·
reconciliation and parity checking · masking or row-access policy translation · Airflow
DAG emission · role and grant replication · CDC.

Each must be addable as a later phase without restructuring what MVP-1 builds.

## 2. Plugin surface

```
oracle-ai-data-platform-workbench-snowflake-migrator/
  .claude-plugin/plugin.json
  commands/        snowflake-assess.md · snowflake-plan.md · snowflake-soft-clone.md
  skills/          5 dirs, each a SKILL.md
  references/      type-mapping.md · gotchas.md · report-formats.md · env-coords.template.md
  engine/          Python, invoked as ${CLAUDE_PLUGIN_ROOT}/engine/...
  docs/specs/      this file
```

| Skill | Item | Responsibility |
|---|---|---|
| `snowflake-migrator-overview` | 1 | Router. Shared auth + safety rules. Entry point; adds no API surface. |
| `snowflake-migrator-bootstrap` | 1 | Verify Snowflake auth, install deps, smoke-test a `SELECT 1`. **Holds no AIDP coordinates.** |
| `snowflake-assess-estate` | 2 | Read-only inventory → `inventory.json` + `INVENTORY.md` |
| `snowflake-migration-plan` | 3 | Dependencies → waves → `plan.json` + `MIGRATION_PLAN.md`, presented for approval |
| `snowflake-medallion-clone` | 4 | Medallion layout, DDL generation, gated deploy → `ddl_plan.json` + `DDL_PLAN.md` |

No agents in MVP-1. Reviewer subagents earn their place once there is output worth
reviewing independently.

## 3. Pipeline and artifact contracts

Each step consumes the previous artifact and emits one machine-readable JSON plus one
human-readable markdown report. Every step is independently re-runnable, and no step
reaches past its input.

```
Snowflake ──▶ inventory.json ──▶ dependencies.json ──▶ plan.json ──▶ ddl_plan.json ──▶ [AIDP]
              (item 2)           (item 3)              (item 3)      (item 4)
```

### 3.1 `inventory.json`

```
{ probed_at, session{user,account,region,role,warehouse,version},
  databases_in_scope[], object_count, counts_by_type{},
  identifier_case_collisions{},        # non-empty ⇒ HALT
  extraction_notes[],                  # per-object failures, never silent
  inventory[ InventoryRecord ] }
```

`InventoryRecord`:

```
source_identifier            "DB.SCHEMA.OBJECT"
object_type                  TABLE | VIEW
source_database, source_schema
identifier_case_form         UPPER_UNQUOTED | MIXED_QUOTED_CASE_SENSITIVE
row_count_exact              in-session count(*), authoritative; null + row_count_error on failure
source_metadata              bytes, created_on, comment, cluster_by, is_dynamic,
                             is_iceberg, is_secure, is_materialized, owner,
                             change_tracking, retention_time
columns[]                    ordinal, name, data_type, is_nullable,
                             numeric_precision, numeric_scale,
                             character_maximum_length, datetime_precision, comment
view_text_show               SHOW VIEWS.text, verbatim (VIEW only)
view_ddl_get_ddl             GET_DDL(), verbatim (VIEW only)
migration_status             discovered | assessed | planned | awaiting_approval |
                             schema_created | blocked | skipped
compatibility_status         unassessed | supported | requires_manual_design | blocked
risk_level, recommended_approach, evidence_location
```

Row counts come from `count(*)` in-session, which is strongly consistent. `SHOW TABLES`
row estimates are informational and are never substituted for it.

### 3.2 `dependencies.json`

```
{ edges[ {from, to, kind, source} ], source_used, coverage_note }
```

**Dual-source, because `OBJECT_DEPENDENCIES` lives in `SNOWFLAKE.ACCOUNT_USAGE` and
requires a grant a customer may refuse:**

1. **Preferred** — `SNOWFLAKE.ACCOUNT_USAGE.OBJECT_DEPENDENCIES`, `source: "account_usage"`
2. **Fallback** — parse `view_ddl_get_ddl` (already captured in item 2) for referenced
   object names, `source: "parsed_ddl"`

`source` is recorded per edge. A plan built on parsed DDL is never presented as
authoritative lineage. MVP-1 therefore has **no external privilege dependency**.

### 3.3 `plan.json`

```
{ waves[[ source_identifier ]],          # topological layers
  namespace_strategy, medallion_assignment{ source_identifier: BRONZE|SILVER|GOLD },
  medallion_assignment_basis{ source_identifier: matched_rule | fallback | user_provided },
  target_names{ source_identifier: target_fqn },
  blocked[ {source_identifier, reason} ],
  unsupported[ {source_identifier, feature, resolution} ],
  cycles[[ source_identifier ]] }
```

Wave ordering: dependency depth, then object size, then type. Usage-frequency ranking is
an explicit extension point for when item 5 returns.

### 3.4 `ddl_plan.json`

```
{ target{ datalake_ocid, workspace, cluster_id, catalog },   # runtime-supplied, never persisted to config
  statements[ {source_identifier, target_fqn, sql,
               rules_applied[], warnings[], omitted_properties[]} ],
  blocked[], dry_run: true|false, executed_at }
```

Carries the `RuleApplication` / `RewriteResult` / `UnsupportedDDL` audit shape from the
a named-rule audit trail, so every transformation is attributable
to a named rule.

## 4. Engine layout

```
engine/
  requirements.txt          snowflake-connector-python · cryptography · oci · requests · websocket-client
  snowflake_source/
    conn.py                 auth: keypair | pat | password | externalbrowser
    extract/catalog.py      SHOW · GET_DDL · INFORMATION_SCHEMA → inventory.json
    extract/dependencies.py dual-source → dependencies.json
    dialect/types.py        Snowflake type → Spark/Delta type
    dialect/identifiers.py  case-folding policy + collision detector
  plan/
    waves.py                topological layers, cycle detection
    medallion.py            namespace strategies + layer assignment
  target/
    coords.py               runtime-only target resolution
    ddl.py                  DdlPlan → Spark SQL CREATE TABLE
    deploy.py               dry-run default; batched replay + per-statement probe
    publish.py              durable registration; feature-detected
    aidp_executor.py        ← fork, unchanged: OCI-signed REST + Jupyter WebSocket
    cluster_session.py      ← fork, unchanged
    cluster_lifecycle.py    ← fork, unchanged
  report/render.py          artifact → markdown
  tests/                    fixtures/ + offline suites
```

Each module answers: what it does, how it is called, what it depends on. `extract/` never
imports from `target/`; `target/` never imports from `snowflake_source/`. The artifacts in
§3 are the only interface between them.

I/O is injected: `catalog.py`, `waves.py`, `medallion.py`, `ddl.py` and `types.py` take
callables or plain data, so they unit-test with no live connection. This is deliberate —
the fork's equivalent logic is tangled into a 9,614-line file and is untestable offline.

## 5. Namespace strategy (item 4)

Generic by default, overridable when the user provides a mapping.
`--namespace-strategy`, default `layer-catalog`.

| Strategy | Target name | Notes |
|---|---|---|
| `layer-catalog` **(default)** | `<layer>.<source_schema>.<table>` | Matches the reference architectures' catalog-per-layer. **Loses the source database**, so two source DBs contributing the same `schema.table` collide → HALT |
| `preserve-source` | `<source_db>.<source_schema>.<table>` | Zero collisions, exact 1:1. Layer recorded as a table property, not in the namespace |
| `layer-flattened` | `<layer>.<source_db>_<source_schema>.<table>` | Layers visible and collision-free, at the cost of mangled schema names |

Layer assignment, in precedence order:

1. **User-provided mapping** — explicit `source → layer`, wins over everything
2. **Generic name heuristic** — `bronze|raw|stg|staging|landing` → BRONZE ·
   `silver|curated|clean|conformed` → SILVER · `gold|mart|dm|datamart|reporting` → GOLD
3. **Fallback** — BRONZE, recorded as `basis: "fallback"`

An object assigned by fallback is **reported, not silently defaulted**, and the full
proposed mapping is always presented for approval before anything is created.

Collision detection runs before DDL generation and **halts rather than guessing**.

## 6. Type mapping (item 4)

Precision and scale are read from `INFORMATION_SCHEMA.COLUMNS` and **never inferred from
sampled data**.

| Snowflake | Spark / Delta | Note |
|---|---|---|
| `NUMBER(p,s)` / `DECIMAL` / `NUMERIC` | `DECIMAL(p,s)` | Highest-consequence mapping. `DOUBLE` only on explicit opt-in, recorded as a warning |
| `TIMESTAMP_NTZ` | `TIMESTAMP_NTZ` | **Not `TIMESTAMP`** — Spark's default is session-timezone-dependent |
| `TIMESTAMP_LTZ`, `TIMESTAMP_TZ` | `TIMESTAMP` | Semantic difference recorded as a warning |
| `TEXT` / `VARCHAR(n)` / `CHAR` | `STRING` | Length not enforced by Delta; recorded |
| `BOOLEAN`, `DATE`, `BINARY`, `FLOAT`/`DOUBLE` | `BOOLEAN`, `DATE`, `BINARY`, `DOUBLE` | Direct |
| `VARIANT`, `OBJECT`, `ARRAY` | **blocked** | Semi-structured. Reported, never approximated |
| `GEOGRAPHY`, `GEOMETRY` | **blocked** | No target type |

**Landing target is an INTERNAL AIDP catalog only.** ADB/ADW/ALH appear in AIDP as
EXTERNAL, read-only JDBC catalogs and cannot hold a managed Delta table; `deploy.py`
asserts the target catalog is INTERNAL before emitting anything.

Properties dropped, each recorded in `omitted_properties`: `CLUSTER BY`,
`DATA_RETENTION_TIME_IN_DAYS`, `CHANGE_TRACKING`, `MAX_DATA_EXTENSION_TIME_IN_DAYS`,
tags, masking policies, row-access policies.

Snowflake PK/FK/UNIQUE constraints are metadata only and unenforced; Delta does not
enforce them either. They are captured in the inventory and reported, not emitted as
enforced constraints.

## 7. Safety model

Driven by the requirement that target coordinates arrive at conversation time.

1. **`coords.py` cannot discover or persist a target.** It reads only arguments passed in
   that invocation. It does not consult environment variables, config files or any cache,
   and there is no code path that writes coordinates to disk. Absent coordinates raise a
   hard error instructing Claude to ask the user.
2. **Dry-run is the default.** `deploy.py` requires `--execute` *and* all four of
   `--datalake-ocid`, `--workspace`, `--cluster-id`, `--catalog` present in the same call.
3. **Approval does not carry across turns.** Skills instruct Claude to confirm in the turn
   it executes, never on the strength of an earlier yes.
4. **DDL is written to a file and shown before execution is offered.** Generation and
   execution are separate commands.
5. **No `CREATE OR REPLACE`, no DROP.** `CREATE TABLE IF NOT EXISTS`; HTTP 409 means
   "already exists", not failure.
6. **Read-only against Snowflake, always.** Item 2 and 3 issue only `SHOW`, `SELECT`,
   `DESCRIBE`, `GET_DDL`.
7. **Secrets are never echoed.** Auth takes a key path or a token read from a file;
   credentials never appear in artifacts, reports, or conversational output.
8. **Every run appends to `migration_audit_log.jsonl`** — planned and executed actions
   both.

## 8. Error handling

The governing rule: **fail loudly on anything unrecognized.** An unmapped type, unmapped
property, unknown dialect construct or unparsed DDL is an error or an explicit
`blocked` / `requires_manual_design` record with the resolution named. Never a silent
default, and never an approximation presented as a conversion.

| Condition | Behaviour |
|---|---|
| Identifier-case collision | **HALT.** Non-zero exit, collisions listed |
| Dependency cycle | Recorded in `plan.json.cycles`, those objects `blocked`, rest proceeds |
| Per-object extraction failure | Recorded in `extraction_notes`, extraction continues. **Throw only if every object failed** — "no objects" and "load failed" are different outcomes |
| Unmapped type | Object `blocked`, feature named |
| Target catalog is EXTERNAL | Refuse before emitting DDL |
| Batched DDL reports success | **Probe each statement's existence individually** — a chunk can report success while statements inside it failed |
| Missing target coordinates | Hard error; instruct Claude to ask |
| HTTP 409 on create | "exists" — not a failure |

AIDP consistency, treated explicitly: an in-session Spark `count(*)` is authoritative; a
catalog REST listing is eventually consistent and informational, so absence is not proof
of absence; HTTP 202 is not confirmation and must be polled.

## 9. Testing

**Offline first, no credentials.** `SHOW`, `INFORMATION_SCHEMA` and `GET_DDL` responses
are recorded from a live estate into `tests/fixtures/` and replayed. Type mapping,
identifier collision detection, medallion assignment, wave computation, cycle detection
and DDL generation are all covered with no Snowflake and no AIDP connection.

Live tests are gated behind `SNOWMIG_LIVE=1`, split read-only / mutating, following the
pattern in MAXWELL's `aidp-cluster-tools`.

The fixture generator is the corpus at `engine/snowflake_source/corpus/00_rappi_setup.sql`
(idempotent, deterministic) verified by `validate.py` — 33 checks asserting referential
integrity, PK uniqueness, join fan-out and two exact business invariants. Row-count
floors alone cannot detect a "right-shaped but wrong-answer" result, which is why the
invariants exist.

## 10. Scope of reuse

This plugin shares only the AIDP workbench plugin *layout* with its sibling
plugins. Nothing behavioural is inherited: the engine, skills, commands and
docs are Snowflake-specific and were written for this plugin. Two shapes were
worth adopting rather than reinventing:

**The DDL audit trail** — `RuleApplication` / `RewriteResult` / `UnsupportedDDL`.
Attributing every schema change to a named rule is what makes a generated
migration reviewable.

**The no-COMMENT-on-schema-create workaround** — `CREATE SCHEMA ... COMMENT`
silently fails to persist on AIDP, so `COMMENT` is never emitted on a schema
create.

## 11. Deferred but designed for

`publish.py` implements durable table registration — assert writable catalog, infer
fields, register, poll the async operation to SUCCEEDED, confirm in-session — because
implicit CTAS auto-registration races the AIDP metastore and leaves tables not durably
visible cross-session. This path depends on a GA API surface whose availability in the
target deployment is unverified. `publish.py` **feature-detects it at runtime** and falls
back to explicit `CREATE TABLE` plus an in-session existence confirmation, recording which
path was used. MVP-1 creates empty tables, so the race is low-consequence; the interface
exists now so that adding data movement later does not require restructuring.

## 12. Acceptance criteria

MVP-1 is complete when the plugin can:

1. be installed as a Claude Code plugin and route from a natural-language request to the
   right skill;
2. authenticate to Snowflake by key-pair, PAT or password, and report clearly which;
3. list every table and view in a scoped estate with **exact** row counts, byte sizes, and
   full column types including precision and scale;
4. record `identifier_case_form` per object and **halt on collision rather than guess**;
5. build a dependency graph from either source, labelling which, and emit topological
   waves with cycles reported rather than silently broken;
6. present a medallion assignment — including which objects were assigned by fallback —
   and a high-level plan, for approval;
7. generate target DDL with every transformation attributable to a named rule and every
   dropped property recorded;
8. refuse to touch AIDP without runtime-supplied coordinates and an explicit in-turn
   confirmation;
9. create empty managed Delta tables in an INTERNAL catalog and confirm each one
   individually;
10. identify unsupported objects explicitly rather than approximating them;
11. run its full regression suite offline from fixtures, with no Snowflake or AIDP
    connection.

## 13. Open assumptions

1. **`layer-catalog` is the right default.** "Use the generic unless it was provided" was
   read as: generic strategy by default, user mapping overrides. Cheap to change — it is a
   parameter, not a structural commitment.
2. **AIDP target coordinates will be supplied per conversation.** No environment has been
   verified; no DataLake OCID exists on this machine. Item 4 is therefore built
   dry-run-first, and its execute path is unverified until coordinates arrive.
3. **Views are inventoried, not translated.** Item 2 captures view DDL verbatim and item 3
   plans views into waves, but item 4 clones **tables only**. View translation is a
   later phase.
4. **Row counts are affordable.** `count(*)` per object is exact but costs warehouse time.
   At large scale this needs sampling or `SHOW TABLES` estimates with the trade-off stated;
   MVP-1 counts exactly and labels the values as exact.

## 14. Relocating work already written

Four files exist today at the plugin root, written while validating access. They predate
this layout and move under `engine/` as the first implementation step. Nothing is
rewritten; `discover.py` is renamed and its I/O split out.

| Current | Target | Change |
|---|---|---|
| `snowflake_source/extract/discover.py` | `engine/snowflake_source/extract/catalog.py` | Rename. Extract connection handling into `conn.py`; keep the inventory logic, case-form capture and collision detection as-is |
| `snowflake_source/extract/probe.py` | `engine/snowflake_source/conn.py` | Keep only `connect()` (keypair/pat/password/externalbrowser) and the row/JSON helpers. The single-object probe path is retired — `catalog.py` scoped to one object supersedes it |
| `snowflake_source/corpus/00_rappi_setup.sql` | `engine/snowflake_source/corpus/00_rappi_setup.sql` | Move only |
| `snowflake_source/corpus/validate.py` | `engine/snowflake_source/corpus/validate.py` | Move only |

`catalog.py` already satisfies most of acceptance criteria 3 and 4. What it still needs
for MVP-1: byte sizes surfaced into `InventoryRecord.source_metadata` (already collected,
not yet promoted), and incremental/resumable extraction so a large estate can be crawled
across runs.

isolated to connection and event-loop handling.

### Assumptions from §13, resolved

1. **`layer-catalog` default** — held. On the live estate it produced
   `bronze.PUBLIC.<table>` with no collisions.
2. **Coordinates supplied per conversation** — held, and enforced by a test that
   inspects `coords.py` for env/file reads.
3. **Views inventoried, not translated** — held. The view is captured verbatim,
   ordered into wave 2 behind its base tables, and reported as unsupported.
4. **`count(*)` affordable** — held at this scale (7 objects, ~20s including
   connection). Untested at 200k objects; sampling remains a later concern.

### Deviations from the plan, and why

| Plan said | Reality |
|---|---|
| `pytest.ini` with `pythonpath = .` | `tests/` is a package, so the shared `fake_sql` double was not importable. Now `pythonpath = . tests` |
| `--out-dir` on the top-level parser | argparse rejects a parent option placed after the subcommand. Moved to a shared parent parser inherited by every subcommand |
| `get_run_sql` appended to `cluster_session.py` | That API does not exist. The fork is asyncio-based with a module-level `cluster` singleton and an `execute(code)` coroutine that runs Python, not SQL. Replaced by `target/aidp_runner.py` with tested `wrap_sql` / `unwrap_outputs` helpers |
| — | The repo-root `.gitignore` has a `target/` rule for Rust/Maven artifacts, which silently untracked `engine/target/`. Re-included from the plugin's own `.gitignore` |
| — | `SCRUBBED_PROPERTIES` included `rows`/`bytes`/`created_on`/`owner`, so the DDL report listed observational metadata as "dropped properties with no Delta equivalent". Split into real properties vs informational metadata |
