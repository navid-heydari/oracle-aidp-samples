Everything the plugin, the plan and the reports currently rest on. Each entry
says what happens if it is wrong. Reviewed 2026-09-16.

## A. Assumptions about the source

| # | Assumption | If wrong |
|---|---|---|
| A1 | A read-only Snowflake grant is enough | Nothing changes: the transport refuses writes regardless of the grant |
| A2 | `count(*)` per object is affordable | At 200k objects this costs real warehouse time. Needs sampling, with the trade-off stated |
| A3 | `ACCOUNT_USAGE` will be granted | Lose observed credits and usage-ranked prioritisation; sizing falls back to declared warehouse size, which says nothing about actual load |
| A4 | `OBJECT_DEPENDENCIES` is readable, else view-DDL parsing suffices | The fallback covers **view→object edges only**; the graph is partial and is labelled as such |
| A5 | `GET_DDL()` returns the full view definition | A truncated definition would produce a wrong view. Both `GET_DDL` and `SHOW VIEWS.text` are captured verbatim so they can be diffed |
| A6 | The test estate is representative | It is not. 7 objects, no stored procs, tasks, streams, pipes, masking policies, or `VARIANT` columns. Nothing here is evidence about a 200k-object estate |

| B2 | The target catalog is **EXTERNAL/SNOWFLAKE** unless the user explicitly asks otherwise | `snowmig.py catalog` registers it: a read-only pointer at the live source that copies nothing. | B2a | ~~The `connectionDetails` shape for an EXTERNAL/SNOWFLAKE catalog~~ **RESOLVED — live-enumerated by the API itself (2026-09-16)** | The map nests under `connectionDetails.connectionProperties`; the allowed keys are `SNOWFLAKE_HOST/PORT/USERNAME/PASSWORD/DATABASE_NAME/WAREHOUSE/ROLE/AUTHENTICATION_METHOD/PRIVATE_KEY_FILE/PRIVATE_KEY_CONTENT/PRIVATE_KEY_PASSPHRASE` + `WORKSPACE_KEY/WORKSPACE_NAME`; the auth enum is `Basic\|KeyPair`; there is no PAT and no schema property. | B6 | Notebooks belong in the workspace filesystem | **Live-verified**, with a correction: the migration tree is `backup-snowflake-migration/` at the workspace root (relative paths; a leading `/` is a 400), and it appears on cluster filesystems under `/Workspace/`. Catalogs hold tables and views, not notebooks |

| B8 | `SHOW`'s `rows` column is exact for a settled standard table | Live-verified against all six corpus tables, where it matched `COUNT(*)` exactly. **Not** verified generally: it can lag very recent DML and is not maintained for external tables, which is why reports label it `show_metadata` and never call it verified |
| B9 | `SHOW ... LIMIT n FROM '<name>'` resumes *after* that name, in name order | This is how the inventory pages past the 10k `SHOW` cap. If the semantics were inclusive, an object would be listed twice; if unordered, paging would miss objects. Worth confirming on a >10k estate — the corpus is far too small to exercise it |
| B9a | `SHOW … LIMIT n FROM '<name>'` resumes exclusively, in name order | **Live-verified** on the test account: `SHOW` output is name-sorted, the cursor is never repeated, the next page starts immediately after it, and a full paged walk equals the unpaged list. Supersedes the "worth confirming" note on B9 |
| B10 | The `LIKE` escape character is backslash | Used to escape `_` and `%` when probing for an exact name. Snowflake and Spark both default to backslash |
| B11 | The legacy path family (`/20240831/dataLakes/…`) keeps working | The current REST reference documents `/20260430/aiDataPlatforms/…` with an `aidp-async-operation-key` waiter; the legacy family is what one live migration verified. The structure-clone transport stays on legacy until a live run proves the new one; everything NEW (`provision_api.py`) is built on the documented contract. If legacy dies, `executor.py` migrates to the documented paths — the shapes are already written down |
| B12 | Cluster library items carry `package` (PYPI) / `path` (WORKSPACE_FILE) / `coordinates` (MAVEN) | The PATCH /libraries envelope and item types ARE documented; the artifact-name field is not. Confirm against a UI-installed library on the first live run |
| B13 | ~~Job task fields and parameter delivery~~ **RESOLVED live (2026-09-16), the hard way** | Tasks require `runIf` and a per-task `cluster: {clusterKey}`; NOTEBOOK_TASK takes `notebookPath` + `source: WORKSPACE` and **runs SUCCESS**; PYTHON_TASK takes `filePath`, is accepted at creation, and **fails every run** resolving the file on the validated build. Job `parameters` reach the notebook **neither as argv nor as environment** (probed on a real run), so jobs execute GENERATED driver notebooks with inline arguments. `/Workspace` is the live-verified mount of workspace files on cluster filesystems |
| B14 | The `workspace-object` surface is how files reach the workspace | **Live-verified** via the `aidp` CLI (4.2.1): relative paths only (leading `/` is a 400), `--type FOLDER/FILE/NOTEBOOK`, `--is-overwrite`, output prefixed with a literal `Response:` line. The Jupyter contents API on the same build returned 200 on PUT and then 404/500 on read-back, and its VolumeContentsManager cannot create directories — it is not trusted for anything |
| B15 | The AIDP **Snowflake connector** reads the source from the cluster | **Live-verified**: `spark.read.format("aidataplatform").option("type","SNOWFLAKE")` read a table (87 rows × 9 cols) and ran `pushdown.sql`, with no extra cluster library. Raw option names differ from the Python helper's: `user.name`, `database.name`, `authentication.method` ∈ {Basic, KeyPair}, `private.key.content`; a wrong one fails `DATA_ACCESS_LAYER_0001`. The `schema` option must name a REAL schema — `INFORMATION_SCHEMA` there is `DATA_ACCESS_LAYER_0031`, though a session scoped to a real schema may QUERY `INFORMATION_SCHEMA` freely. Snowflake numerics arrive as `decimal.Decimal`, which `json.dumps` refuses |
| B16 | The external catalog's **crawler** can fail while the connector works | **Live-verified, and unresolved.** Registration succeeds and the catalog is ACTIVE, but `actions/refresh` and `actions/testConnection` both fail `CONNECTOR_0067 — Login has timed out`, with the same credentials the connector uses successfully from the cluster. Not an FQDN form: the org-account and account-locator hosts resolve to the same backend and both fail identically; the cluster's own egress to :443 was proven. The crawler runs outside the cluster's network path, and every other external catalog on that DataLake is Oracle-network ATP/ADW. Consequence: **connector mode is the default source mode**, and external-catalog mode waits for a deployment whose crawl succeeds |
| B19 | The target accepts every type the mapper emits | **FALSE, live-verified 2026-09-19.** The HIVE METASTORE behind an AIDP catalog refuses `timestamp_ntz` at `CREATE TABLE` with `InvalidObjectException: Invalid column type: timestamp_ntz`, even though Delta and Spark 3.4+ support the type and the CREATE runs on compute rather than through the catalog API. So "Delta supports it" is not sufficient: the metastore is a second, stricter gate. The remedy is the existing `--timestamp-ntz timestamp` mapping flag, which is a SEMANTIC downgrade (session-timezone instant vs wall-clock) and is recorded as a warning, never applied silently. `ddl` now HALTS (exit 3) on any type in `TARGET_REJECTED_COLUMN_TYPES` rather than letting the plan reach a workflow: the check is offline and instant, the failure it replaces cost a full job run |
| B17 | `testConnection` needs an EXISTING catalog | **Live-verified**: it resolves RBAC `DESCCATALOG` on the `key`, so a probe against a name that does not exist fails `NotAuthorizedOrNotFound` rather than testing anything. Register first, then test |
| B18b | In connector mode, **every source read opens a Snowflake session** | **Measured live**: per-table counting cost more session setup than the copy itself, so the copy batches a schema's source counts into one UNION ALL per 50 tables. `--verify counts+sums` still costs a read per table, which is why it stays opt-in |
| B18 | Job **startup** dominates small work | **Measured live**: ~5–6 minutes wall clock for a job run that did almost nothing. So the operating unit is a SCHEMA, never a table, and 100 CTAS creates (one Snowflake round trip each) is the wrong shape — `--mode ddl-plan` applies the engine's already-translated types with no source read |

## C. Assumptions in the mapping

| # | Assumption | If wrong |
|---|---|---|
| C1 | Bronze mirrors the source 1:1 (database → Standard Catalog) | Stated by the requirement. `--bronze-catalog-prefix` is the only variation |
| C2 | AIDP supports three-level namespaces | If not, names must flatten and collisions become possible again |
| C3 | `NUMBER(38,0)` → `DECIMAL(38,0)`, not `BIGINT` | 38 digits overflow 64 bits, so `BIGINT` would corrupt values |
| C4 | `TIMESTAMP_NTZ` → Spark `TIMESTAMP_NTZ` | Spark's bare `TIMESTAMP` is session-timezone-dependent; the wrong choice shifts every timestamp |
| C5 | A view body with no Snowflake-only construct runs unchanged on Spark | Plausible but unproven — no view has been executed on AIDP. Every generated view carries a warning to verify against the source |
| C6 | 7 of the 8 implemented dialect rules are exact; `DATEADD` is exact for DATE operands only (a TIMESTAMP operand is truncated to DATE) and the DDL plan records that caveat (`R43`) instead of calling the view exact | Reviewed, not executed. `LISTAGG` refuses `WITHIN GROUP` and `::` refuses expression operands rather than guessing; `DATEADD` refuses expression amounts, quoted units and nested-call arguments |
| C7 | Snowflake PK/FK/UNIQUE need not be emitted | Neither engine enforces them. They are captured and reported |
| C8 | `VARIANT`/`OBJECT`/`ARRAY` as `STRING` is a deferral, not a mapping | Offered only via `--semi-structured string`, never by default. Nothing on the target can address a field inside the text, so any query using Snowflake path syntax stops working until a typed design is agreed |
| C9a | Snowflake exposes no `OPTIMIZE` / `VACUUM`, and reclaims storage automatically | Documented behaviour; layout is maintained by Automatic Clustering, not a user command. Confirmed on the test account: every table `cluster_by=''`, `automatic_clustering='OFF'`, 0 reclustering events and 0 credits in `ACCOUNT_USAGE` |
| C9b | AIDP supports `OPTIMIZE`, `VACUUM`, `ZORDER BY` and liquid clustering | Delta 3.2.0 OSS, and **live-verified by the sibling AIDP workbench plugin** through *its* execution path — not through this plugin's. See D9 |
| C9c | `cluster_by`, `retention_time`, `data_retention_time_in_days` and `change_tracking` have AIDP equivalents | They do, and were previously reported as having none. Now deferred with the equivalent named, never applied. `MAX_DATA_EXTENSION_TIME_IN_DAYS`, Fail-safe and Search Optimization genuinely have no equivalent |
| C9d | Maintenance cadence and retention are the customer's to set | Both need recovery requirements and query patterns this plugin cannot see. It reports the gap and proposes nothing — see `ACTION-ITEMS.md` |
| C9 | `TIME` → `STRING` is acceptable with a warning | Spark has no `TIME` type. The value survives; ordering, comparison and time arithmetic become string operations, so it is warned rather than silent |

## D. Assumptions in the plan and reports

| # | Assumption | If wrong |
|---|---|---|
| D1 | Dependency depth then size is a sensible wave order | Usage-frequency ranking is the better input and is a documented extension point |
| D2 | Risk levels are meaningful | Derived from observable facts (view, dropped properties, timezone warnings, row count), not judgement. Adjust the thresholds if they mislead |
| D3 | The CLI status model tops out at `SHALLOW_CLONE` | By construction: `summary` reads the control-plane deploy result and never `reconciliation.json`, so it cannot report `DATA_CLONE`/`DONE`. Copy status is reported only by `snowmig_03_reconcile` (`MIGRATION_REPORT.md`) after `snowmig_02_copy_schema` has run. Breaks if: someone reads `SUMMARY.md` as the data verdict |
| D4 | One catalog per deploy is safer than fanning out | A multi-database estate spans catalogs; one approval must not authorise all of them |
| D5 | ~~`DESCRIBE` shapes~~ **SUPERSEDED.** Structure is verified through the catalog API, not SQL | **Live-verified.** `GET /tables/<key>` returns `tableFields` with `fieldName`/`fieldType`/`fieldPrecision`/`fieldScale`. The LIST response carries no fields at all, which is why structure needs a GET |
| D6 | ~~`SHOW` name columns~~ **SUPERSEDED.** Existence comes from `GET /tables?catalogKey=&schemaKey=` | **Live-verified.** Objects are keyed `<catalog>.<schema>.<name>`, and `schemaKey` must be fully qualified or the call returns 400 |
| D7 | Comparing column name, type and order is a sufficient structure check | It does not compare nullability, comments or column-level metadata. A difference in those would report as verified |
| D10 | AIDP lower-cases every identifier | **Live-verified.** A schema created as `TEST_DB` is stored as `test_db`. Targets are planned folded, and keys are additionally resolved from the server. This makes the case-collision detector load-bearing: `ORDERS` and `"orders"` fold together and the run halts |
| D11 | Catalog creates are asynchronous and can fail silently | **Live-verified.** `POST` returns 202 with an empty body and **no `opc-work-request-id`**, so there is no waiter. The object appears seconds later or never, and a failure reports nothing. Read-back polling is the only sound method |
| D12 | A failed create permanently poisons that name in that schema | **Live-verified**, including that `DELETE` does not recover it. The only recovery found is a different schema. See P1–P3 in `ACTION-ITEMS.md` |
| D13 | A view's column types are DERIVED by the target, not carried over | **Live-verified.** Three aggregate columns of a 17-column view changed type, two of them narrowing. Reported as `derived_type_drift`, distinct from a mismatch |
| D9 | The maintenance statements will execute through THIS plugin's backend | **Unverified.** `OPTIMIZE`/`VACUUM`/`CLUSTER BY` are confirmed on AIDP by the sibling plugin's path; this plugin has never run them. Item M8 in `ACTION-ITEMS.md` |
| D8 | `DROP SCHEMA` is permitted at the destination | Used only by `smoke --write-probe --execute`, on exactly one per-run uniquely-named schema (`snowmig_permission_probe_<8 hex>`), never `CASCADE`, and only on the schema that run itself created. The no-`DROP` rule is a **source** guarantee and does not extend to AIDP |
