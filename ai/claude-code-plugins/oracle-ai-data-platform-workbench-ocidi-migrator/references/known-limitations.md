## No faithful automatic form (reported `manual`)

- **Pipeline Decision operators.** A job's `runIf` cannot evaluate a
  condition, so tasks behind a decision are left out of the job. Split the
  branches into separate jobs, or add a notebook that checks the condition
  and exits.
- **OCI Data Flow tasks.** Their Spark code is in Object Storage, not in
  OCI-DI. Fetch it and host it as a notebook or a python task.
- **Fusion Apps (BICC/BIP), REST data assets.** Land the data on AIDP first
  (the `aidp-fusion-bicc` connector, or fusion-autopilot), then map the asset
  in `ocidi-config` `sources`.
- **MERGE targets with no key** and **parameterised target entity names.**
  A Delta table needs a fixed name and a merge key.

## Work orders an LLM may or may not complete

- **OCI Function operators.** The function's code is not in the export, so
  the author should decline unless the behaviour is unambiguous.
- **`ORA_HASH`, `LISTAGG`, numeric `TRUNC`, `INSTR` with position or
  occurrence, locale-aware `TO_CHAR`/`TO_NUMBER`.** Values can differ from
  Oracle; the author must state an `# ASSUMPTION:`.
- **Custom-SQL sources.** Source-dialect SQL rewritten for Spark against the
  source catalog.
- **SQL tasks.** A JDBC procedure call through the JVM with an AIDP
  credential. Needs the driver on the cluster.
- **Table Function operators.** No SDK model; the operator config is passed
  verbatim.

## Semantics to confirm per migration

- **Write mode IGNORE** is read as `mode("ignore")`. **BACKUP** is written
  as OVERWRITE; Delta time travel keeps the previous version.
- **OVERWRITE fed by an incremental source.** Each run replaces the table
  with only that run's rows (as OCI-DI did). Finding `TG08`.
- **Lookup RETURN_FIRST / RETURN_LAST.** Spark has no lookup-source row
  order, so one matching row is kept, not necessarily DI's first or last.
- **Join outputs with duplicate column names.** The left side's value is
  kept unless the DI output port lists both. Finding `JN03`.
- **Pivoted column names** follow Spark's convention, not DI's column-name
  pattern.
- **Schedules.** Only exact conversions are emitted ("every N days/hours"
  usually has none). Start/end windows are dropped. One schedule per job.
  Everything is created PAUSED.
- **`SYS.TASK_RUN_KEY` and similar system parameters** are generated by the
  notebook, not by AIDP; their values have a different format.
- **Watermarks** are seeded from the *start* of the last successful DI run.
  Conservative (it may re-read), never skipping.
- **Type alignment.** Writes are cast to the target table's types. A value
  that would become NULL stops the write instead of loading silently.

## Out of scope

- Moving historical data out of the old DI targets. Reconcile reads them;
  it does not copy them.
- Creating clusters, external catalogs, credentials or bucket policies. They
  are listed in `sources.md`; use the engineer-agent skills to create them.
- Running or unpausing jobs, and pausing the OCI-DI schedules. These are the
  user's cutover steps.
